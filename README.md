# voice-clone

HTTP voice-clone service based on XTTS v2 (Coqui TTS). Trains a voice from a
short reference audio and then synthesizes text with that voice — as full
audio, in streaming, over a websocket, or played back directly through the
machine's speakers.

This branch (`serbot-prod`) is meant to run exclusively on a
**Jetson Orin with JetPack 6.2 (L4T R36.5)**.

## Requirements

- Jetson with JetPack 6.2 (L4T R36.5) and the NVIDIA driver already
  installed (`nvidia-smi` must work).
- `sudo` access (to install system packages via `apt`).
- Internet connection (downloads the XTTS v2 model, ~2GB, the first time the
  service starts).

`conda` is not used: the Python 3.10 that ships with JetPack out of the box
already satisfies what `TTS==0.22.0` requires (`python<3.12`).

## Installation

```bash
git clone <repo> voice-clone
cd voice-clone
./deploy/install.sh
```

The script is **idempotent** — it can be run again on top of an existing
installation without breaking anything; each step checks whether it's
already done before repeating it.

### What `install.sh` does

1. Checks that `nvidia-smi` exists (assumes JetPack is already installed).
2. Installs `ffmpeg` via `apt` if missing.
3. Installs the CUDA 12.6 and cuDNN 9 runtime libraries via `apt`
   (`cuda-cudart`, `cuda-nvrtc`, `cuda-libraries`, `cuda-cupti`, `libcublas`,
   `libcufft`, `libcurand`, `libcusolver`, `libcusparse`, `libnvjitlink`,
   `libnvfatbin`, `libcufile`, `libcudnn9-cuda-12`). These are needed
   because the Jetson PyTorch wheel assumes the system CUDA Toolkit is
   already present — it doesn't bundle it.
4. Creates the virtual environment in `.venv/` with `python3 -m venv` (no
   conda).
5. Appends the CUDA `LD_LIBRARY_PATH` to the end of `.venv/bin/activate`, so
   it's set automatically every time the environment is activated.
6. Installs PyTorch with CUDA support from the **Jetson AI Lab** community
   index (`https://pypi.jetson-ai-lab.io/jp6/cu126`), because the official
   `download.pytorch.org` wheels are x86_64-only and don't work on Jetson
   (aarch64 architecture).
7. Installs the rest of the dependencies from `requirements.txt` (`TTS`,
   `transformers`, `fastapi`, etc.).
8. Since `TTS` can overwrite the GPU-enabled PyTorch while resolving its own
   dependencies, it's reinstalled with `--no-deps` to restore the Jetson
   build, and `numpy<2` is pinned (compatible with torch 2.8; `TTS` asks for
   `numpy==1.22.0` but that's only an install-time pin, not something it
   checks at runtime).
9. Patches `TTS/utils/io.py` inside the venv: since PyTorch 2.6, the default
   of `weights_only` in `torch.load` changed to `True`, which breaks loading
   the XTTS checkpoint (it carries config objects, not just tensors).
   `TTS==0.22.0` doesn't pass that argument explicitly, so
   `kwargs.setdefault("weights_only", False)` gets added.
10. Creates the `models/`, `speakers/`, `logs/` folders.
11. Generates `.env` with a random `VOICE_CLONE_API_TOKEN` (if missing) and
    `VOICE_CLONE_AUDIO_DEVICE=plughw:2,0` (if missing).
12. Installs `voice-clone.service` and `voice-clone.timer` into
    `~/.config/systemd/user/` and runs `daemon-reload`.

### Manual steps after `install.sh`

The script doesn't enable the timer automatically (so the config can be
reviewed first). Run once:

```bash
systemctl --user enable --now voice-clone.timer
sudo loginctl enable-linger $(whoami)
```

- `voice-clone.timer` starts `voice-clone.service` **1 minute after every
  boot** (don't use `enable --now voice-clone` directly on the `.service`,
  it would skip the delay).
- `enable-linger` makes the `--user` service keep running after closing the
  SSH session (without this, systemd kills user services on logout).
  Requires `sudo`, run once per user.

### Repeating it on another Jetson

1. Confirm it's JetPack 6.2 / L4T R36.5 (`cat /etc/nv_tegra_release`) and
   Python 3.10 (`python3 --version`). If the JetPack version differs, adjust
   `TORCH_INDEX_URL` in `install.sh` (the `jp6/cu126` segment changes
   depending on the CUDA version that JetPack ships) and the `cuda-*-12-6`
   package versions accordingly.
2. Clone the repo and run `./deploy/install.sh`.
3. Verify the audio output device (`aplay -l`) — if the USB card isn't
   `card 2`, adjust `VOICE_CLONE_AUDIO_DEVICE` in `.env`.
4. Enable the timer and linger (commands above).

## Configuration (`.env`)

| Variable | Description | Default |
|---|---|---|
| `VOICE_CLONE_API_TOKEN` | Bearer token required on every endpoint except `/health`. Auto-generated by `install.sh`. | — |
| `VOICE_CLONE_AUDIO_DEVICE` | ALSA device used by `/synthesize/play` (see `aplay -l`). | `plughw:2,0` |
| `VOICE_CLONE_MODEL_DIR` | Folder where the XTTS v2 model is cached. | `./models` |
| `VOICE_CLONE_SPEAKERS_DIR` | Folder where trained voice latents are persisted. | `./speakers` |
| `VOICE_CLONE_LOG_DIR` | Service log folder. | `./logs` |
| `VOICE_CLONE_MAX_QUEUE` | Maximum size of the GPU job queue. | `10` |
| `VOICE_CLONE_GPU_MEMORY_FRACTION` | Fraction of GPU memory reserved for the model. | `0.9` |
| `VOICE_CLONE_MAX_TEXT_LENGTH` | Maximum text length per synthesis. | `2000` |
| `VOICE_CLONE_CORS_ORIGINS` | Comma-separated list of allowed CORS origins (e.g. `https://app.example.com,http://localhost:5173`). If unset or empty, CORS middleware is disabled entirely. | — |

## Manual usage (without systemd)

```bash
source .venv/bin/activate
uvicorn server:app --host 0.0.0.0 --port 9000
```

## API

Every endpoint except `/health` requires the header
`Authorization: Bearer <VOICE_CLONE_API_TOKEN>`.

### `GET /health`

No authentication. Reports whether the model is loaded and whether it's
using GPU.

```bash
curl http://localhost:9000/health
```

### `POST /train`

Uploads a reference audio (WAV, max 45s / 5MB) and trains the latents for a
voice.

```bash
curl -X POST http://localhost:9000/train \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@audio.wav" \
  -F "speaker_id=default"
```

### `GET /voices`

Lists the trained voices.

### `DELETE /voices/{speaker_id}`

Deletes a trained voice (memory and disk).

### `POST /synthesize`

Returns the full generated audio (WAV) for a text.

```bash
curl -X POST http://localhost:9000/synthesize \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello, this is a test.", "speaker_id": "default", "language": "es"}' \
  --output result.wav
```

### `POST /synthesize/play`

Synthesizes the full audio first, then plays it directly on the Jetson's
speakers (via `aplay`/ALSA) and streams it back to the client at the same
time (same chunk format as `/synthesize/stream`: raw float32 PCM), so the
frontend can play it back in sync.

Full generation happens before any audio is sent — on this hardware, XTTS
streaming generation can't keep up with real-time playback (roughly 1.5-2x
slower), so chunk-by-chunk streaming from the model produces audible
stutters. Generating the whole clip first adds latency before playback
starts, but once it starts it plays without gaps.

```bash
curl -X POST http://localhost:9000/synthesize/play \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello, this is a test.", "speaker_id": "default", "language": "es"}' \
  --output frontend_test.raw
```

### `POST /synthesize/stream`

Returns the audio in chunks (raw float32 PCM) as it gets generated, as a
`StreamingResponse`.

### `WS /synthesize/stream-text?token=<TOKEN>&speaker_id=<id>&language=<lang>`

Websocket for bidirectional streaming: text is sent in fragments (not
necessarily complete sentences) and audio comes back in chunks as soon as
each sentence completes. The stream is closed by sending the literal text
`<END>`. The token is passed as a query param because the websocket
handshake doesn't support custom headers from every client.

## Monitoring the service (systemd `--user`)

Since it's a user service, every command needs the `--user` flag:

```bash
# Current status (active/down, PID, memory, latest log lines)
systemctl --user status voice-clone

# Live logs
journalctl --user -u voice-clone -f

# Last 100 lines without following live
journalctl --user -u voice-clone -n 100 --no-pager

# List all --user services running
systemctl --user list-units --type=service

# Confirm the timer is scheduled
systemctl --user list-timers voice-clone.timer
```

The application also keeps its own log at `logs/service.log`.

## Notes / known issues

- **PyTorch isn't on standard PyPI for Jetson.** The
  `download.pytorch.org` wheels are x86_64; the Jetson AI Lab index has to
  be used instead (see `install.sh`), which publishes builds per JetPack
  version.
- **The system CUDA Toolkit is a separate requirement from the PyTorch
  wheel.** The Jetson AI Lab wheel assumes `libcudart`, `libcublas`,
  `libcudnn`, etc. are already installed via `apt` — if they're missing,
  `import torch` fails with `OSError: lib*.so.* not found`.
- **`torch>=2.6` breaks loading XTTS checkpoints** due to the `weights_only`
  default change. Patched in `install.sh` (step 9 above). If `TTS` gets
  updated to a version that already handles this, the patch can be removed.
- **Don't run `pip install -r requirements.txt --no-deps` by hand** — it
  would leave `TTS`/`transformers` without their real dependencies. The only
  place `--no-deps` is used is to specifically reinstall
  `torch`/`torchvision`/`torchaudio` after `TTS` may have overwritten them.
